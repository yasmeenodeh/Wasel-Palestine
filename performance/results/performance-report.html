Identified Bottlenecks

  • Baseline read-heavy, spike, and soak results were dominated by throttling, causing high rejection rates.
  • Write-heavy traffic remains the most expensive path because report submission triggers validation, duplicate checks, audit logging, and inserts.
  • Mixed workload still shows high p95 latency because writes pull the tail latency upward even when the error rate is zero.

Observed Limitations

  • The baseline run measured security throttling as much as application capacity.
  • The optimized write-heavy scenario still hits endpoint business rules under sustained report intake.
  • The report reflects local single-node Docker behavior, not a distributed production deployment.

Root Causes

  • Default throttler settings were too strict for benchmarking and produced artificial 429-style rejection behavior.
  • Report creation is a multi-step write path, so latency grows faster than read endpoints.
  • Listing endpoints depend on sort and filter patterns that benefit directly from indexing.
